# Branch C 范围与迭代记录

本轮工作依据 proposal 第 2 页 Branch C、proposal 第 3 页训练及评价要求，以及 PPT 第 10、11、13 页。保持真实视频摘要描述符、Isolation Forest / one-class 模型、连续异常证据和按组 OOF 的既定路线。没有增加局部区域分支、深度特征编码器、镜头检测模块、额外检测算法或新的研究任务。

## 第一轮：基础约束与数据接入

| 问题 | 修正 | 验证依据 |
| --- | --- | --- |
| 部分 JSON 配置会接受错误类型，生成器字符串被拆成字符 | 验证整数、有限数、列表、未知字段及采样时间网格 | 配置/API/CLI 回归测试 |
| 拟合时会读取不参与训练的生成 train | fit 只读取真实 train 和全部 val，保留完整清单元数据 | 删除生成 train 和 test 文件后仍能拟合 |
| 合成清单默认可能被标为 research | 自动继承 synthetic_smoke，禁止改报，分数 CSV 保留来源 | 默认 fit/OOF、CSV 和 CLI 拒绝测试 |
| 新测试清单可能与模型属于不同协议 | 保存和校验 protocol，解码前检查重复 ID、路径和组 | 异协议和换 ID 复用路径回归测试 |
| 时间网格可能超出实际 EOF，短视频边界不严格 | 仅保留完整采样间隔，检查原始解码时长，记录尾部差值 | 2 秒、20 秒及非整网格时长测试 |
| 纯真实子集出现误导性的 macro-F1=0.5 | 不可定义的二分类指标返回 null，保留误报率 | 单类别、相同分数、无预测阳性回归测试 |
| 逐行比较历史分组开销随数据规模快速增长 | 预先建立 ID、路径和分组集合 | 原有及新增防泄漏测试 |
| 提取进度混入命令行 JSON，影响自动读取 | 进度写入 stderr，stdout 保持单个 JSON | 29 个输入片段触发进度后的 CLI JSON 解析测试 |

解码器版本已进入特征签名。旧缓存不会被新流程复用，旧模型需要按新签名重新拟合。此变更用于确保训练和推理使用一致的预处理。

第一轮验证：72 项自动化测试通过；两种既定算法均完成合成数据拟合、固定阈值评价和 5 折 OOF。Isolation Forest 另完成 MP4 解码、NPZ 与帧接口一致性验证。历史结果保存在 `artifacts/proposal_iteration_01`。测试中的小型真实验证池会产生阈值分位数粗糙的预期提示。

## 第二轮：限定模型比较与资源测量

本轮依据 proposal 中限定超参数比较、验证集选择、测试封存和运行资源统计要求，补齐已有实验路线的执行工具。

| 改进 | 实现与约束 | 验证 |
| --- | --- | --- |
| 有限模型比较 | 新增 select；IF 4 个组合、SVM 2 个 nu；特征与评价协议一致 | 6 个候选均完成真实类拟合及 val 评分 |
| 明确选择规则 | val AUROC、macro-F1、预定顺序；原始 IF 基线优先精确并列 | 重复运行计划哈希、排名与模型标识一致 |
| 防止选择阶段读取 test | 只准备真实 train 与 val；共享同一批特征 | 删除生成 train 和全部 test 文件仍成功；缓存恰好 10 个测试夹具输入 |
| 保留比较审计 | 冻结计划、每候选 val CSV、实际读取 ID/哈希、选定配置及模型；失败不输出完成报告 | 候选失败和运行期间修改清单回归测试 |
| 明确耗时口径 | predict 新增分阶段 timings；benchmark 用独立进程统计启动在内与模型加载在内耗时 | 阶段求和、CLI JSON 和预测分数一致性检查 |
| 记录峰值内存与输入条件 | worker 的原生进程 RSS、平台单位转换、模型体积、环境/线程与输入哈希；视频记录原始尺寸 | macOS/Linux 单位测试、2 次独立 worker 测试，10 秒 TOY MP4 实测 3 次 |

验证结果：**90 项自动化测试通过，15 条小型真实 val 阈值粗糙的预期提示**。完整 TOY 流程、两种既定算法的拟合/评价/5 折 OOF、选定配置的 5 折 OOF 和固定阈值评价均通过。新增资源命令在 160×120、30 fps、10 秒 TOY MP4 上完成 3 次测量，报告保存在 `artifacts/proposal_iteration_02/runtime_10s.json`。这些测量只验证代码和本机 TOY 输入，不是正式数据上的速度或检测结论。

最新合成结果在 `artifacts/proposal_iteration_02`，源文件与验证证据摘要在 `validation/verification.json`，更新后的交接包在 `output/branch_c_handoff.zip`。本轮没有修改描述符、评分方向或解码时间规则，第一轮模型保持兼容。

## 第三轮：失效案例、输入记录和缓存可靠性

本轮继续执行 proposal 的可复现、已知失效案例与模型卡要求，保持既定异常检测方法与评分规则。

| 问题或缺口 | 修正 | 验证 |
| --- | --- | --- |
| NPZ 原始帧尺寸被二次验证时的工作尺寸覆盖 | 保留 input_width/input_height，单列 feature_image_size；视频 native 条件另列 | 48×64 输入缩放为 32×32 后仍正确记录原尺寸；数值描述符不变 |
| 同时准备同一输入会争用固定缓存临时文件 | 独立临时文件、完整写入后原子替换、失败清理 | 强制两个冷缓存写入者同时运行，最终只有一个完整缓存；模拟磁盘错误后无残留 |
| 读取期间输入可能变化而污染缓存键 | 提取后再次核对内容哈希，变化时不写缓存 | 提取中修改文件的回归测试 |
| 旧缓存没有可靠的新元数据字段 | 缓存格式独立升级为 descriptor-cache-v2，隔离旧缓存并验证字段/类型 | 旧格式隔离、损坏元数据和数值类型测试；不变更模型特征签名 |
| 结果缺少方便人工填写的误报/漏检清单 | evaluate 导出 error_review.csv，列固定阈值 FP/FN、输入条件、空白原因和笔记 | 覆盖 FP/FN/TP/TN、等于阈值和零错误；案例计数与混淆矩阵一致 |
| 部分评价目录可能覆盖人工记录 | 已有分数或审阅表即拒绝；两份 CSV 成功后才写完成报告 | 保护人工笔记、报告写入失败和早期拒绝测试 |
| 分数文件无法直接核对实际输入字节 | val、候选、OOF 和 test CSV 增加 content_sha256 | 导出哈希逐行对照原输入；错误数量/格式拒绝测试 |
| 开发状态和已验证结论容易混淆 | 增加开发阶段 MODEL_CARD.md，列正式数据、评价和人工审阅待办 | 对照 proposal 第 4 页模型卡与局限性要求，不填入虚构实验结论 |

验证结果：**112 项自动化测试通过，17 条小型真实 val 阈值粗糙的预期提示**。完整 TOY 特征/拟合/OOF/评价/MP4 流程通过；既定 IF/SVM、有限候选选择与选定配置 OOF 继续可用。旧模型在 NPZ、MP4 上的整段和窗口分数与第二轮保存的结果精确一致，原始帧尺寸记录已修正。原始分数不是概率，FP/FN 只是固定异常阈值下的二分类评价定义；人工原因仍为空。

本轮最终验证保存在 `artifacts/proposal_iteration_03_verified`；`artifacts/proposal_iteration_03` 保留为加入分数哈希前的开发运行。旧缓存保留，新格式重新提取元数据，已有第一、二轮兼容模型无需重拟合。最新源文件哈希和证据摘要更新到 `validation/verification.json`，交接包更新到 `output/branch_c_handoff.zip`。正式数据目录当前仍不存在，不将软件测试或 TOY 测量当作正式实验完成。

## 第四轮：公共折提前准备与输入冻结

本轮依据 PPT 第 11 页的共用训练折与折外评分要求，以及 proposal 的视频组隔离和固定种子训练控制，完善 C 与其他分支的接入。

| 改进 | 执行约束 | 验证 |
| --- | --- | --- |
| 新增 folds 命令 | 只哈希 train，不解码、不拟合，不读取 val/test 文件；保留原始清单与分区 | 使用无法解码的独特 train 字节文件、删除 val/test 文件仍完成分折 |
| 提前交付公共清单 | 导出 manifest_with_folds.csv、无预测的 fold_assignments.csv 与 fold_plan.json | 路径从新目录可解析，标签/来源/分区/自定义字段保持一致 |
| 固定计划身份 | 计划由 clip_id、标签、分组、输入哈希和实际折号确定；OOF 保存复用的 plan_id | 复用/重排行映射时计划标识一致；原顺序下折号和 C 分数精确一致 |
| 数据不足尽早报错 | fit 在读视频前检查真实 train/val；OOF 在提取前检查折号、组隔离、真实拟合数量 | 缺少真实类、折号缺失/非法、组跨折和真实样本不足的回归测试 |
| 完全重复文件不能跨折 | 训练文件哈希并入连通组，先检查后提取特征 | 变更 ID/组但复用字节的跨折输入被拒绝；自动分折将重复文件留在同折 |
| 冻结输入版本 | 可选 content_sha256 清单字段，缓存命中与冷提取前均强制核对 | 训练文件替换、错误摘要格式及冷热缓存的解码前拒绝测试 |
| 保护部分训练结果 | 已有 fit/OOF 报告、分数或分折文件即拒绝覆盖；fit 报告在验证分数后写入 | 部分产物保护测试；完整流程交付检查 |

验证结果：**134 项自动化测试通过，17 条小型真实 val 阈值粗糙的预期提示**。完整 TOY 流程通过；公共计划在 IF、SVM、选定配置的 5 折 OOF 中一致复用。直接 OOF、提前分折后的 OOF 与第三轮保存结果的折号和分数逐行精确一致。选定模型和 SVM 的固定阈值评价继续通过，合成来源标记完整保留。

最新产物在 `artifacts/proposal_iteration_04`，公共折入口为 `common_folds/manifest_with_folds.csv`。折计划不含预测，不验证视频解码或 val/test 字节重复，换机器时仍需数据负责人映射路径。原算法、特征、种子和评分规则保持一致；没有取得正式检测效果或融合增益证据。验证记录与交接包同步更新，正式数据仍待交付。
